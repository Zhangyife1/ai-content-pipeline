## 一、优化后的简历描述（可直接替换）

> **AI 内容生产管线与企业官网全栈开发 | 技术负责人**
>
> 项目背景：公司需搭建自主可控的官方获客入口，集成 AI 内容自动化、智能客服与基础电商能力，实现从内容生产到发布运维的全链路技术闭环。
>
> **核心工作：**
>
> - **AI 内容管线**：主导「热点抓取 → AI 生成 → 三层质检 → 人工审核 → 多渠道发布」全链路设计，基于 Python 实现多源内容聚合器（RSS/Mock）与检索增强生成（RAG + HyDE）多步生成链；Prompt 版本化入库并接入 Dify 可视化编排与异常重试；批量生成并发 8 路，内容生产人效提升约 8 倍。
> - **RAG 智能客服**：基于 Coze 知识库（RAG 能力）构建官网 FAQ 智能问答机器人，支持多轮上下文记忆；通过 Function Calling 对接订单查询/下单 API，实现「问答 → 查询 → 下单」交互闭环；同步自研同构的 `ChatEngine` 服务（混合检索 + 会话记忆 + 工具路由）作为可审计的工程实现。
> - **全栈工程**：独立完成 15+ 页面响应式前端与后端表单系统（PHP + MySQL）；设计数据库 Schema，落地五层性能优化策略，首屏加载从 4.2s 降至 1.1s；上线后服务器负载率从 90% 优化至 43%，可用性 99.9%。
> - **GEO 工程化**：落地 Schema.org 结构化标记（Article/FAQ/Organization）、自动 Sitemap 生成与提交；完成阿里云 ECS 部署、CDN 加速、SSL 证书与 WAF 防护。
>
> **项目成果**：上线 3 个月核心业务关键词首页覆盖率 60%+，自然流量增长 220%；系统可用性 99.9%。

## 二、Coze Bot 能否包装为 RAG 系统？

**结论：可以，但有边界。**

Coze 知识库 = 文档切分 + 向量检索 + LLM 生成，本身就是 RAG 产品化形态。因此：

- ✅ 可以写：**“基于 Coze 知识库（RAG 能力）构建 FAQ 智能问答，支持多轮上下文记忆”**
- ❌ 不要写：**“自研 RAG 检索框架”“自研向量数据库”**（除非你真的做了）
- ✅ 建议补：**自研工程层**（Function Calling 订单闭环、会话管理、效果埋点），这部分是你真正写的

面试策略：先讲业务成果（Bot 上线、问答→查询→下单），再讲自研 `ChatEngine`（本仓库 `conversation/`）讲清检索、记忆、工具调用的工程细节。面试官追问“如果不用 Coze 你行不行”时，直接现场演示/讲解自研实现。

## 四、面试追问预案（3 个最可能被追问的点）

1. **“8 倍人效怎么算的？”** → 口径：人工单篇 2-4 小时 vs 管线初稿 3-5 分钟 + 审核 10 分钟；批量并发后更优。要强调“是初稿人效，质检与人工审核保留，不是全无人”。
2. **“Coze 和自研 RAG 有什么区别？”** → Coze 负责知识库检索与生成编排，自研负责工具调用、会话状态、审计与效果数据；两者互补。
3. **“自然流量 220% 是你一个人做的吗？”** → 归属要诚实：GEO/SEO 基建与内容管线由你负责，增长是内容供给量提升 + 结构化数据 + 技术优化共同作用的结果。
